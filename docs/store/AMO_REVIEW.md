# FeedMe — source & build instructions for AMO review

This archive is the complete source for the submitted add-on. The submitted
`dist/*.js` files are **generated** (bundled and minified from `src/` with
esbuild), so this source archive and these instructions are provided per AMO's
policy for generated or bundled code.

## Toolchain

- **Node.js 24.13.1** (pinned in `.nvmrc`; `package.json` `engines` requires
  `>=24.13.1 <25`). Use `nvm use` to match.
- **npm** as bundled with that Node.
- No other system tools are needed to reproduce `dist/`.

## Reproduce the submitted build

From the root of this archive:

```
npm ci            # install exact dependencies from package-lock.json
npm run package   # esbuild → dist/, then assemble build/firefox/
```

`npm run package` runs `esbuild.config.mjs` (produces `dist/`) followed by
`scripts/package.mjs`, which copies `dist/`, `popup/` and `icons/` plus a
generated `manifest.json` into `build/firefox/`. The contents of
`build/firefox/` are byte-for-byte what was submitted, minus the outer zip.

- The manifest is generated per target by `scripts/manifest.js` from
  `manifest.base.json` and the `version` in `package.json`; it is never
  hand-edited.
- The Firefox manifest is what `web-ext lint` runs against. The release script
  (`npm run release`, `scripts/release.mjs`) gates on
  `web-ext lint --source-dir build/firefox --warnings-as-errors`.

## What is not in this archive

`node_modules/`, `build/`, `dist/` and `.playwright-mcp/` are excluded — they
are generated by the commands above or are local tooling, and are reproduced by
`npm ci && npm run package`.

## Data handling

The add-on has no server of its own and transmits nothing to the developer or
any third party. Its only network traffic goes to the delivery platforms the
user is already logged into, reproducing requests those platforms' own pages
make. The Firefox manifest declares `data_collection_permissions: none`
accordingly — see the reasoning in `scripts/manifest.js`.
